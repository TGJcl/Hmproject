二、两大核心工作流（ChatAgent）

同一个 Agent 通过上下文自动识别当前工作流；两者共享 RAG 检索与事实记忆，仅任务目标、分支判断和落库逻辑不同。

工作流一
健康档案采集 HEALTH_PROFILE
逐项采集 8 个字段，建档完成后按病史查饮食建议
用户发送健康信息（“我28岁，170cm，60kg，有高血压…”） ▼ ChatAgent.run → API Key 校验（缺失则弹窗索取） ▼ standardRun：加载 prompts/agent_prompt.md 提示词 ▼ embed 用户输入（ModelWorker 线程 · jina 向量模型） ▼ RAG top3 检索 vector_memory（档案 / 膳食知识 / 事实） ▼ 组装提示词（当前日期 + 未痊愈状况 + 当前档案 + 记忆片段） ▼ DeepSeek → 严格 JSON（mode=profile + fields + reply） ▼ handleContent：抽取 8 字段（年龄/身高/体重/睡眠/运动/症状/病史/周期） ▼
分 未收齐 → 回复追问下一个缺失字段（↺ 回到用户输入，循环） 已收齐 → saveHealthProfile → 向量化 → vector_memory（health_profile）
▼
分 history ≠ “无” → DietAdviceService：维基百科查询 → DeepSeek 归纳 → web_diet_advice 入库 history = “无” → 跳过
▼ 工作流重置为 AI_QA · profile 清空 · facts 事实入库 ▼ 页面展示“档案已存入记忆库 + 饮食注意事项” · 对话记录落库
工作流二
健康问答 AI_QA
RAG 检索回答 + 食物确认（food_check）子流程
用户提问（文字）或上传图片（YOLO 识别出食物标签） ▼ ChatAgent.run / runWithImage → API Key 校验 ▼
分 图片识别到食物 → 组问题“识别到 xx，能否食用？” 未识别到 → 回退为文字问答
▼
判 有 pending_food_question → finishFoodCheck：清空 pending → RAG → DeepSeek（携带“原问题 + 用户确认”）→ 明确回答 无 pending → standardRun：embed → RAG top3 → 提示词（含未痊愈状况列表）→ DeepSeek
▼
分 mode=qa → 直接回复 mode=food_check → 保存 pending_food_question（Preferences）→ 模型逐一确认未痊愈状况 → 等待用户回复（↺ 回到 runCore）
▼ facts 事实入库（新增 active / 痊愈 resolved） ▼ 页面展示回复 · 对话记录落库（conversation_message）

四、各个模块流程图

核心业务链路，从用户输入到结果展示。

4.1 统一对话主流程（档案采集 / 健康问答 / 事实记录）

用户发送消息（文字 / 图片） ▼ ChatAgent.run / runWithImage ▼ ModelWorkerService.embed 向量化（Worker） ▼ VectorDatabase.search → RAG 检索结果 + 打分 ▼ 拼提示词（当前未痊愈状况 + 档案 + 记忆片段 + 用户输入） ▼ DeepSeek → 返回严格 JSON ▼ ChatAgent.handleContent 解析 ▼
分 mode=profile → 抽取 8 字段建档 mode=food_check → 进入食物确认 mode=qa → 直接回复
▼ facts 事实入库（去重 / 生命周期） ▼ 页面展示回复 · 对话记录落库

4.2 健康档案采集 + 饮食建议流程

用户提供健康信息（“我28岁，170cm…”） ▼ mode=profile · 抽取 fields · 逐项追问（8 个字段） ▼ isComplete → 生成档案文本 ▼ MemoryService.saveHealthProfile → 向量化 → vector_memory（metadata=health_profile） ▼
分 病史非空且非“无” 病史为“无” → 结束
▼ DietAdviceService：维基百科 API → 正文 → DeepSeek 归纳饮食注意事项 → 向量入库（web_diet_advice） ▼ 页面展示：档案已存 + 饮食建议

4.3 食物确认流程（模型判定 + 状态持久化）

用户问“西瓜可以吗” ▼ standardRun：未痊愈状况列表进上下文 ▼
判 模型返回 mode=food_check 返回 mode=qa → 直接回答
▼ 保存 pending_food_question（Preferences，重启可续） ▼ 模型先逐一确认未痊愈状况（“感冒现在好了吗？”） ▼ 用户回复“是 / 已经好了” ▼ finishFoodCheck：携带“之前询问 + 确认结果”再问 DeepSeek ▼ 明确回答能否食用 + 注意事项

4.4 图片上传 → YOLO 识别 → 能否食用

点击 🖼️ → ImagePicker（PhotoViewPicker 相册选图） ▼ 预览缩略图（可移除）→ 点击发送 ▼ FoodRecognitionService：PixelMap → RGBA ArrayBuffer ▼ ModelWorker 线程：yolo_init（rawfile 模型字节）→ yolo_detect ▼
分 识别到食物（banana / pizza…）→ 组问题给 agent 未识别到 → 提示 / 回退文字问答
▼ agent 判断能否食用（有未痊愈状况则先确认） ▼ 展示结论

4.5 事实记忆生命周期（active / resolved）

对话中透露新事实（“我患有感冒”） ▼ facts 数组 → metadata：{source:chat_fact, subject, status:active, time} ▼ 向量化入库（同 subject 的 active 不重复） ▼ 用户说“感冒好了 / 痊愈” ▼ 模型输出 status=resolved → 删除同 subject 的 active 记录 ▼ 入库 resolved 事实（时间线保留） ▼ RAG 记忆片段带时间戳 → 模型正确判断当前状态

4.6 ModelWorker 线程调用流程（RPC）

ModelWorkerService.post(type, payload) ▼ pending 表登记 id + Promise ▼ worker.postMessage（ArrayBuffer 走 transfer 零拷贝） ▼ ModelWorker 线程：embed_init / embed / yolo_init / yolo_detect ▼ workerPort.postMessage 回传结果 ▼ 按 id resolve / reject → 主线程拿到结果

4.7 对话记录与记忆检索

每条用户/机器人消息 → ConversationService → conversation_message（health_chat / ai_chat） ▼ 用户提问 → 向量化 → RAG top3 检索 ▼ 记忆片段（档案 / 膳食知识 / 饮食建议 / 事实时间线）拼入提示词 ▼ DeepSeek 依据记忆回答
